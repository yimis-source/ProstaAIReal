## 1. Introducción

## 1.1 Propósito

Este documento especifica los requisitos de software de Prosta-AI, una aplicación web de carácter académico para el análisis de imágenes de resonancia magnética de próstata. Su estructura sigue la norma ISO/IEC/IEEE 29148:2018 (ISO/IEC/IEEE, 2018) y toma como modelo el ejemplo de especificación publicado por Eccam s.r.o. (2021). Sirve de base para el diseño, la construcción y las pruebas del sistema, y está dirigido al Propietario del Proyecto y al equipo de desarrollo.

## 1.2 Alcance

Prosta-AI es una aplicación web experimental que permite cargar estudios de resonancia magnética de prueba, procesarlos de forma automática con un modelo de segmentación 3D y visualizar la región de interés (ROI) sobre la imagen original. El sistema usa únicamente conjuntos de datos públicos y anónimos, y no ofrece diagnósticos ni recomendaciones médicas (Equipo ProstaAI, 2026a).

Esta especificación cubre las siguientes funciones:

Acceso básico a la aplicación.

Carga y validación de estudios de prueba.

Procesamiento automático: control de calidad, preparación, segmentación 3D y generación de la ROI.

Visualización de la ROI con su explicación, sus limitaciones y el aviso de uso experimental.

Registro y consulta de los estudios procesados.

De forma opcional, orientación al usuario mediante agentes de inteligencia artificial.

Quedan fuera del alcance el uso clínico, la validación médica con radiólogos, los estudios con pacientes, los trámites ante el INVIMA, el despliegue en producción con alta disponibilidad, el mantenimiento posterior, la aplicación móvil y la gestión de usuarios y permisos más allá de un acceso básico (Equipo Prosta-AI, 2026a).

Los requisitos de gestión del proyecto, que corresponden a los requisitos 1.1 a 1.4, 6.2, 6.3 y 6.5 de la matriz de trazabilidad (Equipo Prosta-AI, 2026b), se documentan en el Plan de Dirección del Proyecto (Project Management Institute, 2017) y no hacen parte de esta especificación.

## 1.3 Perspectiva del producto

## 1.3.1 Interfaces del sistema

Prosta-AI es una aplicación web con arquitectura cliente-servidor. El frontend se construye con React, el servicio de aplicación con FastAPI, los datos con PostgreSQL y almacenamiento de archivos, y el módulo de inferencia con PyTorch y MONAI (Project MONAI, s. f.). El código y sus versiones se gestionan con Git y GitHub.

## 1.3.2 Interfaces de usuario

La interfaz incluye una pantalla de acceso, una pantalla de carga de estudios, un indicador de estado del procesamiento, un visor por cortes con la ROI superpuesta y un panel de explicación.

En toda pantalla de resultados se muestra el aviso de uso experimental y no diagnóstico. El diseño detallado se presenta en el documento de diseño de la solución (Entregable 3).

## 1.3.3 Interfaces de hardware

El uso del producto no requiere hardware especial. Google Colab, servicio externo con GPU gratuita, se usa solo para entrenar el modelo y para pruebas de inferencia durante el desarrollo; la aplicación en uso infiere en su propio servidor.

## 1.3.4 Interfaces de software

El producto se integra con PostgreSQL y con el almacenamiento de archivos. Los programas 3D Slicer e ITK-SNAP se usan solo para la verificación visual de resultados y no forman parte del producto.

## 1.3.5 Interfaces de comunicaciones

El frontend y el servicio de aplicación se comunican mediante una API. Sus contratos se definen en el documento de diseño de la solución.

## 1.3.6 Otras restricciones

Las restricciones de memoria, las operaciones, la adaptación al sitio y las interfaces con servicios externos no aplican en esta versión.

Prosta-AI tiene un único tipo de usuario, el usuario académico: estudiantes y docentes de Ingeniería de la Universidad Santiago de Cali que usan la aplicación con fines educativos. No necesita formación médica ni conocimientos de programación. Como el alcance excluye roles y permisos (Equipo Prosta-AI, 2026a), no se definen actores adicionales. ## 1.6 Limitaciones

El producto es experimental y académico; no sustituye una evaluación profesional ni un diagnóstico médico.

Solo se usan conjuntos de datos públicos y anónimos, con licencia documentada.

El desarrollo se ejecuta en siete ciclos durante el periodo académico 2026-2, con una fecha de entrega final inamovible.

Los recursos de cómputo son los equipos personales del equipo y servicios gratuitos como Google Colab.

El stack tecnológico está definido de antemano: React, FastAPI, PostgreSQL, PyTorch/ MONAI y Git/GitHub.

No se realiza validación médica ni ensayos clínicos.

## 1.7 Supuestos y dependencias

Se asume que los conjuntos de datos públicos seleccionados tendrán calidad, cantidad y diversidad suficientes para entrenar el modelo.

Se asume que el stack elegido y su documentación pública permitirán al equipo adquirir el conocimiento necesario dentro del tiempo disponible.

Se asume que cada integrante contará con los recursos computacionales mínimos para desarrollar su parte.

El entrenamiento del modelo depende de la disponibilidad de Google Colab.

El uso de los datos depende de que sus licencias permitan el uso académico.

Los supuestos se revisan al cierre de cada ciclo, y los que no se confirmen pasan al registro de riesgos.
