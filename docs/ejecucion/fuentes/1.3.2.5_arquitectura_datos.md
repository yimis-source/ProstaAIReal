Arquitectura de datos de Prosta-AI

Definición La arquitectura de datos describe cómo se gestionan los datos de un sistema, desde que se recopilan hasta que se transforman, se distribuyen y se consumen; es el plano técnico de cómo fluyen los datos por los sistemas de almacenamiento (IBM, s. f.). Dentro del proceso de diseño de software, Sommerville (2011) ubica el diseño de base de datos como una de las actividades de diseño, junto con el diseño arquitectónico, el de interfaz y el de componentes, y su salida es la especificación de la base de datos.

El diseño de una base de datos define su estructura lógica y física: las tablas, los atributos, las relaciones y las restricciones entre las entidades, así como las claves primarias y foráneas de cada tabla. Ese diseño parte de las necesidades de información de los usuarios y de las aplicaciones que usarán la base de datos (Casas Roma, s. f.).

Este documento corresponde al paquete 1.3.2.5 de la EDT (arquitectura de datos) y a la actividad 1309 del Ciclo 2, Diseñar la base de datos. Se basa en la matriz de trazabilidad de requisitos y en las arquitecturas de software y de sistema del proyecto (Equipo Prosta-AI, 2026a, 2026b).

Flujo de los datos En Prosta-AI los datos siguen el recorrido de la Figura 1. Los estudios de prueba se recopilan cuando el usuario los carga; se validan y se desidentifican antes de guardarse; se transforman durante la preparación y la segmentación, y se consumen en el visor de la ROI y en el historial de estudios. La base de datos guarda la información estructurada (usuarios, estudios, trabajos, etapas, modelos y resultados), mientras que los archivos pesados (imágenes, máscaras y pesos del modelo) quedan en el almacenamiento privado y la base de datos solo guarda su ubicación.
